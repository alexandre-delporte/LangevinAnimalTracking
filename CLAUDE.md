## Package Overview

**LangevinAnimalTracking** is an R package implementing particle filtering and statistical inference for animal movement trajectories modeled as penalized Langevin stochastic differential equations (SDEs). The core model is the Rotational Advective Correlated Velocity Model (RACVM) with a mixture-of-Gaussians potential function representing habitat structure and domain constraints.

## Development Commands

All development uses standard R devtools/testthat workflows:

```r
# Build and install (from R)
devtools::install()

# Recompile C++ only
devtools::load_all()

# Run all tests
devtools::test()

# Run a single test file
testthat::test_file("tests/testthat/test_llk_grad.R")

# Regenerate documentation and NAMESPACE
devtools::document()

# Full R CMD check
devtools::check()
```

From the shell:
```bash
R CMD INSTALL .
R CMD check .
```

C++ files are compiled automatically by R when building the package. The `src/Makevars` configures LAPACK/BLAS/OpenMP flags for RcppArmadillo.

## Architecture

### Two-Layer Design

The package has a clear R/C++ split:

- **C++ layer** (`src/`): Performance-critical algorithms — particle filter, SDE/ODE solvers, covariance computations, Gaussian mixture gradients. Uses Rcpp + Armadillo (arma::mat/vec).
- **R layer** (`R/`): Algorithm orchestration, inference loops (PMMH, SGD), Laplace approximation logic, error model definitions, and user-facing API.
- **`R/RcppExports.R`** and **`src/RcppExports.cpp`** are auto-generated by Rcpp — do not edit manually.

### Core Algorithms

| File | Role |
|------|------|
| `R/particle_filter.R` | Main particle filter with Laplace approximation for measurement updates |
| `R/particle_smoother.R` | Forward-filtering-backward-sampling (FFBS) smoother |
| `R/PMMH.R` | Particle Marginal Metropolis-Hastings for Bayesian inference |
| `R/SGD.R` | Stochastic Gradient Descent with Fisher information preconditioning (Baey et al. 2023) |
| `R/llk.R` / `R/llk_gradient.R` | Log-likelihood and gradient w.r.t. model parameters |
| `R/error_models.R` | ARGOS error class parameters; mixture-of-t observation models |
| `R/utility.R` | RACVM covariance/link matrices, parameter transformations |
| `src/particle_filter.cpp` | C++ core: resampling, particle propagation, weight updates |
| `src/sde.cpp` | Exact OU covariance; RACVM transition covariance and mean |
| `src/ode.cpp` | ODE step for splitting scheme (Lie-Trotter / Strang) |
| `src/utility.cpp` | Gaussian mixture gradient, polygon boundary push, Cholesky log-density |

### SDE Splitting Scheme

Particle propagation uses operator splitting to handle both the SDE diffusion and the potential-driven ODE drift:
- **Lie-Trotter:** full ODE step → SDE step
- **Strang:** half ODE step → SDE step → half ODE step

Domain constraints are enforced by reflecting particles at polygon boundaries via `compute_push_cpp()`.

### Measurement Error Models

Three observation models are supported (selected via a string argument to the particle filter):
- `"normal"` — Gaussian errors
- `"t"` — scaled Student-t (heavy-tailed)
- `"argos"` — ARGOS satellite telemetry: location-class-specific mixture of bivariate t distributions (Brost et al. 2015), parameters in `error_models.R`

### Laplace Approximation

The particle filter uses a Laplace approximation (in `R/particle_filter.R`) to integrate out measurement noise analytically, improving efficiency. The C++ function `product_gaussian_cpp()` and `log_dmvnorm_chol_cpp()` support this.

## Testing

Tests are in `tests/testthat/` and focus on mathematical correctness:

- **`helper-set_up.R`** — shared fixtures: test polygon, SDE params (`tau=1, nu=5, omega=0.1`), Gaussian mixture potential params
- **`test_llk_grad.R`** — validates gradients against finite differences (tolerance ~1e-4)
- **`test_laplace_approximation.R`** — tests Laplace approximation for Student-t model
- **`test_log_dmvnorm_chol.R`** — tests Cholesky-based multivariate normal log-density
- **`test_RACVM_derivatives.R`** — tests RACVM covariance and mean derivatives

When adding new mathematical functions, add a corresponding gradient/finite-difference test.

## Key Conventions

- **Parameter names:** `tau` (mean-reversion time), `nu` (speed), `omega` (rotation), `sigma` (noise), `lambda` (domain penalty)
- **Data structures passed to C++:** arma::mat/vec via Rcpp; R lists used for complex return values
- **Cholesky factors** are used throughout for numerical stability in multivariate normal computations
- **`devtools::document()`** must be run after any roxygen2 comment changes to update `NAMESPACE` and `man/`
